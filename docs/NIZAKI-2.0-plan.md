# NIZAKI 2.0 計画(暫定)

神埼鉄道グループの公式アプリを、「情報アプリ」から「使うほど賢くなる、神埼ID中心のアプリ」へ育てる大更新計画。
アプリ名の呼び方は **NIZAKI 2.0**(画面には出さない)。バージョン番号とは別で、公開のときに **4.0.0**(Major)を付ける予定。

最終更新: 2026-10-14 / 状態: 計画段階(未着手は、下の「進め方」を参照)

## 方針
- **骨組みは業務感、中身は架空鉄道らしさ。** 東急・JR東日本・東京メトロ・相鉄のアプリを見て決めた。迷ったら「本物の鉄道アプリにありそうか」で判断する。ありそうなら本物に寄せ、なさそうなものは遊びとして足す。
- **予約とイベントは、タブに残す。** 神埼の「顔」なので、埋もれさせない。
- **費用は、かけない。** GAS・GitHub Pagesの無料の範囲で作る。有料のものは、事前に相談する。
- 他社(実在の鉄道会社)とは関係がない。リンクを置く場合も、提携しているように見せない。

## 参考アプリで分かったこと(スクリーンショットより)
- きっぷ・座席の予約は、4社とも「外部のサービス」。神埼は、予約がアプリの中心なので、タブで残す。
- 設定の置き場は、4社で割れている(メニュー・☰・タブの1つ)。正解は1つではない。
- 4社すべてに、時刻表・遅延証明書・マイ駅・路線図がある。経路検索は、タブか☰か外部のどれかで必ずある。
- 東急・JR・メトロは、共通ID(TOKYU ID など)で、複数のサービスをつないでいる。神埼の「神埼ID」が、同じ役割になれる。
- メトロは、ホームとタブの固定以外を、利用者が選べる(タブのカスタマイズ)。
- 相鉄は、☰メニューが12項目と少なく、神埼の規模に近い。着せ替え(キャラクター・テーマ)がある。

## 柱
1. **賢い案内** … 経路検索(乗換・運賃つき)。ホームに「いまから乗るなら」(次の列車と乗換を、遅れも含めて提案)。
2. **賢い通知** … マイ駅・よく使う路線の遅れや運休を、自動で知らせる。まずはアプリの中。LINEは、無料プランの送信数の上限に注意。
3. **自分の記録** … 乗車記録・マイレージ(ランクが利用で上がる)・駅のスタンプ。
4. **土台の強化** … N-POINT・予約履歴・ミステリーの進行・クーポンの使用記録を、端末の中からクラウド(GAS)へ。端末を変えても引き継がれ、端末のデータを消してもらい直す抜け道がなくなる。保存データの作りが変わるので、これが **4.0.0 の根拠**。

## 公開のしかた(公開日は未定)
- NIZAKI 2.0 の新しい機能は、いつもどおり小さく本番に出すが、**公開日までは画面に出さない**。
- 隠す仕組みは `src/utils/launch.ts`。公開日が決まったら、`LAUNCH_AT` に日時を書く(例: `'2026-10-31T00:00:00+09:00'`)。その日時になった瞬間から、全員に見える(端末の時計を使う)。`null` のあいだは、準備中の機能は見えない。
- **作業用リンク:** アプリのURLの末尾に `?preview=1` を付けて、一度開く(例: `https://nagaimo178.github.io/Nizaki-Railway/?preview=1`)。その端末では、公開前でも新しい画面が見える。戻すときは `?preview=0`。
- 準備中の機能を足すときは、`isLaunched()` で出し分ける。**隠した機能だけの変更は、`package.json` の版番号も `release-notes.json` も変えない。** 版番号が変わると、全員に更新ダイアログが出てしまうため。
- 公開日に、`package.json` を 4.0.0 にして、広報を出す。

## 進め方(おすすめの順)
1. **経路検索(小さく始める形)** … 時刻表タブの中に切り替えで置く。駅から駅・出発時刻を決める形。乗り換えは、同じ駅名での乗り継ぎ(別路線でも、同じ路線の急行から各停でもよい)で、最大5本の列車まで。結果は早い順の3つ。絞り込み(有料特急を使う/乗換の余裕/乗換の回数/リアルタイム検索=遅れを加味)と、詳細表示(停車駅・運賃の内訳)つき。入力と前回の結果は、タブを移っても引き継ぐ。**経由駅**(通ってほしい駅を最大3つ。降りる駅としては扱わず、停車でも通過でも「通った」とする。順番は問わない。運賃は実際に乗った距離)に対応。経由・到着時刻指定・始発/終電は、あとから。**公開日まで隠した状態で、版番号を上げずに本番へ入れる(更新ダイアログを出さないため)。**
2. **土台の強化 + 記録** … 柱4と柱3を一緒に。記録を最初からクラウドに保存して、二度手間を避ける。完了したら **4.0.0 = NIZAKI 2.0 公開**。
3. **賢い通知。**

## 決めたこと・見送ったこと
- 遅延証明書: **作らない**(オーナーの判断)。
- AIの案内係(話しかけて経路や時刻を聞く機能): **作らない**(オーナーの判断。「インテリジェント」は、経路検索・通知・記録の中身の賢さで出す)。
- Nライナーの料金: **いまのまま**(運賃と座席料金の合計)。実在のQ SEATは座席料金だけだが、変えない。
- 予約を別サイトに分けること: **しない**(同じ仕組みが2か所になり、手間が増える)。
- 実在の他社アプリを開くリンク: **置かない**(ブラウザのアプリからは、確実に開けない)。
- 実在の他社線の運行情報を、アプリの中に出すこと: **しない**(外部データの取得と利用条件の手間が大きい)。
- 列車ごとの小さな遅れは、路線の運行状況には出さず、注記で案内する。
- 以前の点検の見送り: 拡大の禁止(E3)はそのまま、`package-lock.json`(E4)は見送り、予約の日付指定(D3)は見送り。
